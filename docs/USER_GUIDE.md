# 使用指南

本指南按网页操作顺序说明。按钮是否可用取决于当前数据条件；遇到限制时先阅读对应原因，不要补造字段或扩大日期范围来通过检查。

## 1. 登录与建立店铺

首次使用选择注册，保存自己的用户名和密码。登录后创建店铺，填写便于区分的名称和说明。不同账号的数据隔离；同一账号可按门店或独立业务建立项目。编辑店铺只修改资料，不会修改已导入的销售记录。

## 2. 上传与预览

在销售总览选择“上传新数据”，或从“数据记录”进入导入流程。支持 CSV 和 XLSX。

- 表头使用一行明确的列名，数据区避免合并单元格、合计行和多个混排表格。
- CSV 中文乱码时核对编码；整行挤在一列时核对分隔符。
- Excel 选择实际营业表所在工作表，不选封面或汇总说明页。
- 查看预览，确认日期、商品编号、数量和金额没有被错误读取，再保存字段对应关系。

上传成功只表示文件已接收。预览、业务确认和分析运行仍需完成。未完成的导入可继续或放弃；不要反复上传相同文件代替检查草稿。

### 一行数据代表什么

| 类型 | 一行的含义 | 可用范围 |
| --- | --- | --- |
| 交易明细 | 一笔订单中的一种商品记录 | 月报；条件满足时客户、共购、日趋势与预测 |
| 商品日汇总 | 一种商品一天的销量或金额 | 月报、日趋势；条件满足时异常与预测 |
| 商品月汇总 | 一种商品一个月的销量或金额 | 月报结构与可比月份分析，无日级走势 |
| 购物篮数据 | 一笔交易中出现的商品集合 | 共购；没有时间和金额时不能用于销售月报 |

## 3. 确认字段与金额

自动对应只是根据列名等信息给出的建议，需由了解表格的人确认。

| 字段 | 应选什么 | 不知道或没有时 |
| --- | --- | --- |
| 商品标识 | 稳定的商品编码，同一商品始终一致 | 不随意把行号或订单号当商品号 |
| 商品名称 | 商户能识别的商品名 | 可用编码定位，名称不代替稳定标识 |
| 类型/分类 | 原表中实物、费用、调整等业务类型 | 保留待确认，不凭商品名猜金额含义 |
| 订单标识 | 同一次购买共享的订单编号 | 留空会限制订单及共购分析 |
| 客户标识 | 稳定的客户编号 | 无客户信息时不进行可靠客户分群 |
| 交易时间 | 实际交易或汇总所属日期 | 确认格式与业务时区，不能使用导出时间代替 |
| 数量 | 对应行的销售数量 | 确认单位，不混合件、箱、重量 |
| 单价 | 每一单位的价格 | 不是该行或整张订单总额 |
| 行金额 | 这一行商品的金额 | 与数量×单价不一致时确认采用的来源 |
| 订单总额 | 整笔订单总金额 | 不把重复出现的同单总额按行相加 |
| 币种 | 金额所属币种 | 统一币种前不混算，系统不自动换汇 |
| 交易状态 | 原表中正常、取消、退货等标识 | 核对原值及含义，不把退货变成正向销售 |

例：一行购买 3 件、单价 5 元，则该行金额为 15 元；如果同一订单还有另一种商品，订单总额可能是 28 元。三种金额不能互相替代。同一列不能随意对应多个含义。修改映射会形成新版本，旧报告仍引用当时的输入与配置。

## 4. 分类、范围与月份

### 业务记录分类

把原表类型值或指定商品编码映射到实物商品、费用/服务、人工调整或待确认。匹配值必须与原值一致；例如源列确实写“实物商品”，才填写这一值。新增但没有匹配值的规则应补全或移除。

金额是否计入与记录类型是两个判断：运费可能属于选定口径的收入，但不应进入实物备货；调整项的金额含义必须由业务人员确认。未知项保留未知。查看分类与金额明细核对分项，不通过“一律实物、一律计入”消除警告。

### 日期与完整范围

- 分析月份应属于实际导入记录覆盖的月份；月汇总需明确所属月份。
- 完整记录开始日和截止日表示已确认没有漏传的营业记录范围，包括没有成交的日期。
- 第一笔和最后一笔销售的日期不一定就是完整覆盖边界。
- 缺失日期仍是未知；确认停业且无成交的日期才填写停业日期。
- 只有核对过原始记录，才能勾选范围完整。缺上月数据或上月不完整时，系统可能不做月度比较。

例如一份确定包含 2026 年 4–9 月全部营业记录的模拟数据，可确认 2026-04-01 至 2026-09-30，并选择 2026-09 分析；真实文件未覆盖这个范围时不能照抄。

追加文件前核对重叠日期与重复记录。追加和重叠替换含义不同；检查选中的版本，避免把同一笔交易计入两次。

## 5. 生成并阅读月报

检查数据，处理阻止生成的错误后确认生成。任务排队时不要重复点击；取消后查看最终状态。生成失败时保留错误提示并检查字段、范围和资源条件。

销售总览展示所选月份的商品数量、销量和可用金额。销售额不等于利润；没有成本不能推导盈利。重点商品是摘要，完整列表在“商品分析”。“接下来先做”最多保留三项优先行动，同类行动会合并，不代表所有分析结果只有三条。

使用历史选择框切换报告，并检查标题月份和链接中的运行标识。重新生成会新增运行；历史结果不会因单纯修改字段草稿而变成新口径。

## 6. 商品、异常与备货

在商品分析搜索、筛选和排序，打开商品查看变化、日走势及来源记录。异常表示相对历史参考出现变化，促销、节假日或录入错误等原因需另行核实。备注记录处理情况；遇到冲突先读取最新备注，不直接覆盖他人编辑。

七天销量参考只在数据与验证条件满足时发布。历史误差说明过去回测表现，不能保证未来准确。没有日级数据、历史不足或误差不合格时，不应强行要求数值。

备货计算需要确认库存快照日期与预测开始日一致，填写可售库存、预测期间内确定到货量、到货日、业务自定备用量和包装单位。历史预测不能搭配今天的库存。系统按预测量加备用量、减库存及有效到货量，再按包装单位向上取整；结果不是采购承诺，也不能保证不缺货。

## 7. 搭配与客户

“搭配建议”与“更多分析”提供商品共购、客户分群及质量依据。满足条件后可查看或运行分析，历史选择代表不同运行，不是不同客户群本身。

- **支持度：** 在分析购物篮中，这些商品一起出现的比例。
- **置信度：** 买了前项商品的订单中，也买后项的比例，方向有区别。
- **提升度：** 相对独立购买假设的关联强度，不是销售增长倍数。
- **RF：** 最近购买时间和购买频次；**RFM** 再加入可靠购买金额。

客户群描述相似购买特征，不是对个人价值的固定评价。共购不证明因果；将商品邻近摆放后还需实际观察效果。完整规则、历史结果和月报优先行动的数量可以不同。

## 8. 销售助手与导出

可询问“本月哪些商品值得关注”“这条建议依据什么”“这个商品为什么没有预测”。复杂或不清楚的问题可能需要澄清。注意页面区分模型解释、确定性回退和数据不足；无论哪种回答都不能替代库存盘点或原因调查。

导出当前报告时先确认店铺、月份和版本。HTML 用于阅读与浏览器打印 PDF；CSV 用于完整商品与逐行审计；JSON 和 manifest 用于结构化核对。PDF 由浏览器打印生成，检查中文、纸张、分页和附页，不把只截首页当完整报告。

导出的文件可能含业务数据，请仅分享给有权查看的人。账号、部署与备份问题见 [安装与部署](DEPLOYMENT.md)，算法解释见 [ALGORITHMS.md](ALGORITHMS.md)。
