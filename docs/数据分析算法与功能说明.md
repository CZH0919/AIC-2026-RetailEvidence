# 数据分析算法与功能说明

更新：2026-10-13。销售算法 `sales-v3.1.1`，销售助手事实协议 `sales-explain-v3`；应用 0.5.0，数据库 schema 5。

系统根据上传数据的粒度和可信程度启用能力：月汇总只做月度结构与比较；完整日记录支持日趋势、预测与异常；可靠订单边界支持共购；可靠客户信息支持 RF/RFM 客户分析。缺少数据时明确降级，不补造信息。

## 正式版本中的算法及功能

| 算法或计算方法 | 对应功能 |
| --- | --- |
| 规则校验、重复候选识别、格式规范化、来源哈希校验 | 导入清洗及可追溯审计；区分未知、零销量、停业和记录缺失 |
| 精确记录类型规则与用户确认 | 区分实物、费用/服务、记账、待确认；费用不进入实物备货 |
| 销售额贡献排序、同额并列排名、累计占比与 ABC 80%/95% 分层 | 商品表现画像和经营重点；金额不可信或样本太少时降级 |
| 完整周变异系数 CV、成交日比例、观察时长及同口径统计比较 | 描述销售稳定性、间歇成交及近期变化；不将未成交解释为缺货 |
| 商品增减贡献、对称数量—成交均价金额拆解（Decimal） | 找出销售额变化的推动/拖累对象，拆解数量与成交均价组成并对账；不当作因果或利润 |
| HistGradientBoostingRegressor（直方图梯度提升回归树） | 根据过去销售和日期特征预测未来七天累计销量，与简单方法比较 |
| 上周销量、四周平均、简单指数平滑 SES、Croston-SBA | 七天预测的基线与候选；Croston-SBA 面向间歇需求；按验证门槛采用或回退，不保证更复杂更准确 |
| 滚动起点评测、MAE/WAPE/偏差、验证期采用门槛、独立末段检查 | 仅用验证期确定方法与回退策略；最后三个时间段只评价固定策略，不根据其得分反向改选。经验范围由校准期决定，测试覆盖率只作诊断 |
| 同星期历史中位数/MAD、Isolation Forest、相邻日期事件合并 | 找出偏离通常表现的商品和日期，给出实际/参考/偏离及源行核对入口；残差 IF 保留对照诊断，不能据此确定异常原因 |
| FP-growth + 支持度/置信度/提升度 + leverage | 挖掘同一订单中经常一起出现的商品，筛选搭配候选，检查热门影响 |
| Wilson 比例范围、独立留出、热门基线、配对分组 bootstrap、多样性排序 | 判断搭配证据可靠性及展示多样性，如实报告是否优于热门推荐；区间不等于未来收益保证 |
| RF/RFM 特征 + log1p + RobustScaler + KMeans | 客户分群；结合 silhouette、子样本 ARI 和群规模诊断选择候选，使用拟合后的同一特征空间计算评分 |
| 库存公式及包装单位向上取整 | 在用户确认的实物商品、库存、到货和预测起点一致时计算七天数量参考；不是自动库存优化模型 |
| 意图/商品规则匹配 + 证据准备 + Qwen2.5-1.5B-Instruct（llama.cpp CPU）+ 服务端事实绑定 | 销售助手解释复合问题，模型只排列允许的事实段落；数字由程序绑定，不能执行 SQL/Python，模型不可用时返回核实事实 |

商品 KMeans 的候选逻辑已经实现，但仍需要业务解释复核，当前不会向用户发布商品聚类结果。STL 是个人目录中的条件实验，未获充分收益证据，未接入正式运行；它及其可选 statsmodels/patsy 依赖不是启动系统的必要条件。预测范围不足时不展示范围，不画未经校验的置信带。

## 分析确认与行动建议

完整性确认、实际覆盖起止日和可用能力说明直接出现在分析确认步骤。未确认完整时仍可查看已提供记录的月报；日期条件满足后，预测和异常还需通过成交历史、有效样本及误差检查，不能仅凭日期范围承诺可用。月汇总不启用日级预测与异常；缺失日不按零销量处理。

行动按记录类型及变化原因分组，组内和组间优先考虑变化影响，并结合销售额贡献与异常幅度；首页最多三项，点击后查看该组排序后的全部相关记录。费用及记账项目保留在核对行动和原金额口径中，不进入首页“重点商品”摘要。排序中的金额影响是参考，不等于实际损失或利润。

类型可在导入字段、商品列表或详情中确认。批量选择只适用于原本类型待确认的记录；已识别费用或记账项需逐项调整。修改类型需明确确认，并沿用该份月报的数据版本、覆盖范围和其他参数生成新月报；不覆盖旧结果，也不把一次确认自动应用到其他历史月报。

## 数据准备与预测可用性

界面统一采用“店铺→上传销售表→确认内容→查看分析”。交易明细或日汇总至少包含商品、日期与数量；整月汇总可省略日期列，但需指定所属月份。多文件合并需主动选择相关表格，上传不会自动合并所有历史数据。

每个未提供预测的商品都记录具体原因及下一步建议：历史不足、缺失日期、早期或近期成交少、处理数量上限、缺少比较记录或验证误差较大；月汇总与覆盖范围未确认也分别说明。沿用原预测门槛：总范围及商品最近记录至少 90 天、候选筛选和最近 28 天至少 4 个成交日、最多 1,000 个历史候选、验证 MAE 不高于 max(2, 近期周均销量的 50%)。本次仅补充原因元数据，不改动预测选择或数量计算规则。旧月报不补造原因，提示重新生成。

销售助手提供按月报／商品上下文切换的示例问题，点击只填入输入框；提问后仍使用服务端绑定事实。无可用预测时，不引导用户进入不存在的库存计算入口。

## 运行资源与兼容性

必要数值依赖固定在 `requirements-mining.txt`，由 `requirements.txt` 引用，包含 numpy、pandas、scipy、scikit-learn、mlxtend。现有环境已满足；本次未升级环境。模型与真实公开数据继续从原 `storage/models` 和 `storage/datasets/public` 读取，路径仍支持原有环境变量。

本次不迁移数据库、不替换用户数据、不导入合成测试项目，不覆盖历史报告。新报告加入可选字段；旧报告仍可查看/导出，只有重新生成的结果才使用新算法。三个主导航、三步上传、五件重点、最多三项行动、库存确认和折叠详情保持。

已有旧质量视图可继续读取；需要使用新增可靠订单日期或客户分组评测信息时，应在当前映射下重新做质量分析并生成新的分析结果，不能把旧视图缺少的字段视为已有数据。

## 已验证的边界

2026-10-12 的历史评测中，两组锁定公开日销量子集候选未达到当时的采用门槛，保留四周平均，同样本误差未改善；其末段曾参与回退，不能将该结果当作 `sales-v3.1.1` 固定策略的独立成绩。Groceries 搭配命中率 24.33%，热门基线 27.28%，因此只将搭配作为历史线索。公开数据异常提醒数量增加，但没有真实原因标签，仍需实际商户评估核对负担。AI 自动绑定检查不等同业务准确率；规则匹配不覆盖任意自然语言。

不要宣称系统能从销售表直接确定利润、缺货原因或促销增量。真实经营收益、完整第四项 UI/文案收尾、全部导入分支与打印分页仍需后续验证。
