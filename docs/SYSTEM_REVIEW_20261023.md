## 发现与修复

| 编号 | 触发条件与原问题 | 修复及保护 |
|---|---|---|
| SP01 | 搜索词命中账号 UUID 前缀，返回名称/说明不匹配的店铺 | 搜索只比较标准化名称和说明，保持账号归属过滤 |
| SP02 | 把销售或算法运行传给质量适用性接口，产生500 | 非质量运行返回409及清楚提示 |
| SP03 | 同项目不同质量运行重用提交键，取得旧输入的分析 | 同时核对运行种类与质量输入；同一请求重试仍幂等 |
| SP04 | 预测177、库存175.6、包装1.4，浮点误差算成2.8 | 用十进制执行包装向上取整，正确值1.4；真实不足仍进一包 |
| SP05 | 已填写表单后短暂断网/服务500，页面被误当退出登录 | 仅确认401清会话；重连遮罩保留草稿并阻止操作旧界面 |
| SP06 | 历史月报经过数据记录/更多分析后返回，丢失所选运行 | 四个顶层入口均保留run参数，支持刷新/前进后退 |
| SP07 | AI响应晚到，用户已经切换报告或商品 | 回答只进入原请求对应上下文，旧响应丢弃 |
| SP08 | 原始行查询晚到，用户已查看另一商品 | 旧行记录不进入另一商品详情 |
| SP09 | 库存计算晚到，用户已切换报告/商品 | 结果绑定报告与商品，禁止跨上下文回写 |
| SP10 | 同商品改库存、包装或确认状态，旧计算仍被当作当前值 | 输入变化使在途结果失效，已保存结果标明“上次保存” |
| SP11 | 检查尚未返回就修改月份/分类，旧检查重新启用生成 | 检查绑定输入和设置版本，变更后必须重新检查 |
| SP12 | 生成月报提交后改设置或关闭重开，旧响应抢走新草稿 | 回调绑定提交时设置；服务器已建立的历史运行仍保留 |
| SP13 | 点击字段文字激活帮助按钮而非对应输入 | 帮助与label分离，使用唯一id/htmlFor连接真实控件 |

后台新增测试在原代码实际得到 **8 FAIL / 3 PASS**，日志 `evidence/before_boundary.txt`。这属于原有缺陷证据，不是最终验收结果。前端慢请求测试采用真实服务器响应，仅延迟其交付；500注入明确标为异常路径，不冒充正常服务表现。

## 视觉调整

延续既有品牌和商业化方向：深青侧栏、浅中性主区域、稳定导航选中态、更清晰的金额与数字层级、规则统一的表格和表单。月报页首辅助入口收进“月报使用帮助”；未映射字段不重复显示同一句小字，已映射字段继续显示真实样例。月度比较提示改为适用于可比较和不可比较两种状态的“如何比较月份”。关键风险、金额口径、分类确认和预测限制仍然可见。

使用原 React / Ant Design，不更换页面业务结构。参考已实际阅读的 [Ant Design 主题配置](https://ant.design/docs/react/customize-theme/) 和 [Shopify 布局指南](https://shopify.dev/docs/apps/design/layout)（2026-10-23）；仅借鉴主题变量、信息密度、间距和任务分组，没有登录其商业后台或复制品牌素材。
