# 分析方法与业务解释

当前核心标识为 `sales-v3.1.1`、`association-v2`、`sales-explain-v4`。算法版本与应用包版本分别记录，复现实验还需固定源码提交、数据、映射和参数。

## 销售统计

先确认记录粒度、日期、数量、金额来源、状态及业务分类，再按月份和商品汇总。单价、行金额和订单总额采用不同处理规则；订单总额不能按每条商品行重复累加。缺失金额不补为零，退货、取消和异常状态不能无提示转为正向销售。

实物商品与费用/服务、调整项及未知项分别处理。用户确认金额是否计入；费用不作为实物备货对象。商品贡献、变化和重点摘要来自实际统计结果，完整清单不受首页摘要条数限制。比较需要口径、币种、单位和覆盖范围可比。

## 七天销量与异常

预测候选包括上一周、四周平均、简单指数平滑、Croston-SBA 和梯度提升方法。按时间划分训练、验证和测试；用验证信息选择方法，以留出数据评测，不因复杂模型存在就默认采用它。发布还受完整范围、历史长度与误差等条件约束。

日异常结合历史参考及异常检测方法提供核查线索，可合并相邻异常事件。无标签数据不能计算真实异常识别准确率，也不能自动认定促销、缺货或欺诈原因。月汇总无法还原日级趋势、异常与七天预测。

备货参考使用已发布预测与人工确认的库存信息：

```text
净需求 = max(0, 七天预测量 + 备用量 − 可售库存 − 期间内有效到货量)
备货参考 = 向上取整(净需求 / 包装单位) × 包装单位
```

快照日期与预测开始日需一致。备用量由业务人员决定；缺少库存或预测时不编造结果。

## RF / RFM 客户分群

R 表示距离最近购买的时间，F 表示有效唯一订单数，M 表示可靠订单金额。R 的参照是观察窗末日之后的本地次日，而非程序运行当天。金额使用有效订单视图，避免重复计数。

特征变换和稳健缩放后使用 K-means，检查候选群数、轮廓系数、稳定性和群体规模。样本量或特征差异不足时限制发布。分群用于理解购买特征，不代表客户真实身份、长期价值或保证可获得的营销收益。

## 商品共购

FP-growth 从有效购物篮提取频繁项集，再计算有方向的关联规则。篮内同商品去重，单商品订单仍属于分母。支持度、置信度、提升度和共同次数必须连同对应数据范围阅读。

训练集建立词表、频繁项集与规则；留出数据用于锁定后的评测，并与流行度基线比较。测试购物篮数量与规则统计分母不同，不能直接用页面上的总购物篮数复算所有训练指标。

完整规则和月报行动不是同一展示：月报按证据与影响范围选择最多三类优先行动，同类做法保留一条，双向商品搭配可合并。只有一条优先搭配不意味着算法只发现一条规则。

## AI 解释

程序提供同一项目、版本和运行下的证据。模型在受限合同内选择解释，数值由程序事实约束，不能执行任意查询或自行补算经营指标。复杂问题、歧义、数据不足、服务失败与校验失败分别处理。模型解释、澄清和模板回退不能合并统计为推理成功。

## 结果适用范围

公开批发数据和模拟便利店数据均不能证明真实小商户的普遍经营效果。关联不代表因果，销量不等于利润，预测量不等于采购量。历史误差及已知验证缺口见 [VALIDATION.md](VALIDATION.md)。
