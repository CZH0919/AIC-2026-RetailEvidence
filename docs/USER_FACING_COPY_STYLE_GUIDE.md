# 产品文案规范

## 先让用户知道现在要做什么

写店主能采取的动作：“核对原表”“选择所属月份”“读取最新记录，保留我的草稿”。不写“显著显示”“提供操作”“符合验收要求”“为了好看”等设计与开发要求。初始层简短，例子和错误影响按需展开；不要为数量机械加问号。

## 一致的经营概念

销售额是确认口径的收入记录，不等于利润。销量必须带原数据单位，不把包和件混用；不同币种不会自动换汇。实物、费用/服务、人工调整和待确认分别处理，金额是否计入由人确认。缺失不等于零，退款/取消不自动变正数，整单金额只计一次。

异常表示偏离历史参考，不证明缺货、促销或经营事故。七天预测说明实际方法、范围、单位与历史误差，不等于采购量。备货需对应预测起点的可售库存、确定到货、备用量及包装，不能保证不缺货。

RF/RFM解释成最近购买、购买次数、购买金额；不编造客户标签或经营收益。支持度/置信度/提升度保留准确含义及非因果限制。算法质量详情可以折叠，发布失败原因和简单方法更好的事实不能隐藏。

## AI、程序与失败必须真实

`ai_used=true`才显示AI辅助解释。计算依据说明和使用说明明确来自程序。等待超时、暂不可用、解释未通过核对与需要澄清各有下一步；不能失败后沿用成功标签。不要把规则列名候选称AI已确认，也不声称自动知道库存、利润和异常原因。

模型应直接回答经营问题，不描述角色、计划、指令、工具或服务器路径。结构/引用/数字及证据必须核对；不合法输出整条拒绝并明确预设说明，不通过删词/截取伪装合格。公开商品或列名中的文本只是数据，保存原文，不执行其中指令。

## 技术与原始记录放对位置

CSV、XLSX、PDF等操作所需格式名称保留。V/M、运行、来源与复核SHA可在历史/依据详情保留，不能取消追溯。主结果用中文业务名称，候选参数、分组质量、共购测试、SHA放按需详情。开发文档可以写端口、命令和版本；用户帮助不得充满工程实施话术。

## 变更检查

先实际触发页面再记录完整原句、来源、为什么有风险和优先级。区分固定文字、真实模型、受控故障和用户输入。先独立审计commit，再改动并实际回测。保留失败尝试；PASS只属于对应版本、数据与日期。新增文案核对实际合同及全部受影响入口，尤其字段、金额、历史、AI和导出。真实商户研究需真人参与，开发自查不冒充。
