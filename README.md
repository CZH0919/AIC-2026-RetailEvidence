# 数证智析 · RetailEvidence Studio

**面向小商户的销售分析与经营复盘工作台。**

将 CSV / Excel 营业表转成可核对的销售月报，连接商品表现、客户购买特征、商品搭配与经营行动。系统保留数据来源、统计口径和分析依据，帮助使用者理解“卖得怎么样、哪些地方值得核查、接下来可以尝试什么”。

**[安装与部署](docs/DEPLOYMENT.md) · [使用指南](docs/USER_GUIDE.md) · [技术架构](docs/ARCHITECTURE.md) · [验证与限制](docs/VALIDATION.md)**

## 产品能力

| 模块 | 主要功能 |
| --- | --- |
| 账号与店铺 | 注册、登录、修改密码、会话管理；账号间数据隔离；店铺创建、编辑、搜索、切换和删除确认 |
| 数据接入 | CSV / XLSX、编码与分隔符、工作表选择、原始预览、导入草稿、字段映射、金额及时间口径确认 |
| 质量与版本 | 缺失、重复候选、订单冲突、取消/退货检查；数据版本、映射与运行记录；逐行排除依据 |
| 销售总览 | 月度销量与销售额、满足条件的月度比较、商品贡献、重点商品和最多三项行动建议 |
| 商品分析 | 完整列表、搜索筛选、变化与日走势、异常日期、原始记录、核查备注及冲突保护 |
| 商品搭配 | FP-growth 共购分析，共同次数、支持度、置信度、提升度和留出评测，历史结果与商品依据 |
| 客户分析 | RF/RFM 特征、客户分群、群体画像和质量诊断，基于实际购买记录的客户关注线索 |
| 销量与备货 | 有条件发布的七天销量参考、历史误差；结合已确认库存、到货、备用量及包装单位计算备货参考 |
| 销售助手 | 根据当前月报或商品证据回答问题；提供澄清、数据限制、模型解释与回退状态 |
| 报告与追溯 | 历史月报、带运行标识的链接；HTML、完整商品 CSV、审计记录、JSON 和清单；浏览器打印 PDF |

系统遵循 **程序计算事实、AI 辅助解释、用户确认业务含义** 的原则。AI 不负责计算金额，不编造库存、利润或异常原因。费用、服务和记账项目与实物商品区分处理，不作为实物备货对象。

## 从数据到行动

```mermaid
flowchart LR
    A[注册并创建店铺] --> B[上传与预览营业表]
    B --> C[确认字段、月份与业务口径]
    C --> D[质量检查与销售月报]
    D --> E[商品、客户与搭配分析]
    E --> F[查看依据、记录处理与导出]
```

进入店铺后，可在 **销售总览、商品分析、搭配建议、数据记录、更多分析** 之间切换。月报生成后按数据条件安排后续客户及共购分析；不适用、无结果和失败分别显示。详细步骤与填写示例见 [使用指南](docs/USER_GUIDE.md)。

### 数据条件决定分析范围

- **商品月汇总：** 支持月度结构和满足口径条件的比较，不能还原日走势或计算日级异常。
- **商品日汇总、交易明细：** 商品、日期和数量支持销售分析；预测还需完整记录范围、足够历史和验证结果。
- **可靠订单与商品记录：** 支持共购；没有真实订单边界时不拼造购物篮。
- **可靠客户、购买时间及订单：** 满足样本要求后支持 RF；金额有效时进一步支持 RFM。
- **缺失信息：** 不补造客户、时间、金额或库存；不同币种和单位不未经确认混算。

销售额不等于利润；异常提示不等于原因确认；预测量不等于采购量；历史共购不代表因果或收益保证。

## 技术与版本

| 层次 | 技术 |
| --- | --- |
| 前端 | React、TypeScript、Ant Design、Vite |
| 后端与持久化 | FastAPI、SQLAlchemy、SQLite |
| 数据处理与挖掘 | pandas、NumPy、PyArrow、scikit-learn、mlxtend |
| 本地模型服务 | Qwen2.5-1.5B-Instruct GGUF、llama.cpp CPU 推理 |
| 分析机制 | 持久队列、单 Worker、受控资源预算、来源与产物哈希 |

当前源码使用 `sales-v3.1.1`、`association-v2`、`sales-explain-v4`，数据库 schema 为 **6**。应用包沿用 `0.5.0` 标记，交付版本以 Git commit 为准。依赖版本由 `requirements*.txt` 和 `frontend/package-lock.json` 固定。

## 安装与使用入口

推荐部署平台为 **Ubuntu 24.04、Python 3.12、Node.js 24**。先安装应用依赖并构建前端，再运行 `bash scripts/run.sh`；默认入口是 `http://127.0.0.1:8000`。AI 是独立可选服务，默认只监听 `127.0.0.1:8081`。

完整的克隆、依赖安装、环境变量、初始化、启动停止、SSH 访问、模型准备、备份恢复及故障排查见 **[安装与部署](docs/DEPLOYMENT.md)**。仓库不包含数据库、商户明细、模型权重或依赖目录。远程服务器的回环地址需经 SSH 隧道访问，不是可对外分享的成果链接。

## 验证与适用限制

验证覆盖公开数据、已知结果的模拟数据、日期边界、账号隔离、前端构建和用户操作记录。测试结论按版本和范围区分：已有日期与上传专项记录，不代表所有新环境或所有业务分支均已验证。

最近一次原样后端套件执行为 **84 通过、50 ERROR（共 134 次执行）**，错误集中在未适配现有鉴权的旧测试准备阶段；这项维护问题尚未修复。构建和专项测试结果、技术报告中的历史实验、未覆盖场景分别见 [验证与限制](docs/VALIDATION.md)。不将工程测试或模拟数据当作真实商户试用、经营收益或全面无缺陷证明。
